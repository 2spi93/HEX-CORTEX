# HEX-CORTEX Project Alignment

## Mission — universality is the objective, coding is the first test ground

HEX-CORTEX is a **model-independent universal cognitive exoskeleton**:
the replaceable AI brain gains access to verified knowledge, formal tools,
specialist cells, perception, world models, planning, memory, criticism,
learning, and gated interfaces to software or physical systems.

The owner's original analogy is **Tony Stark's armor**: the armor should
amplify the capabilities of the model placed inside it. This is a
testable engineering objective, **not a demonstrated numerical multiplier**.

The eventual scope includes mathematics, physics, molecules/chemistry,
biology, engineering, research, computers/software, connected devices,
robots and drones. Coding reliability was selected as the **first measurable
test ground**, not HEX-CORTEX's identity or final capability limit.

HEX-CORTEX must not claim to already possess all knowledge of the universe.
It should access traceable external and local scientific knowledge,
calculate with appropriate tools, represent physical quantities with units,
differentiate truth from hypothesis, simulate where available, and
acknowledge unknowns. Real learning and physical actuation require independent
evidence and safety boundaries.

See [universal mission and knowledge/embodiment architecture](UNIVERSAL_CORTEX_NORTH_STAR_V12.md).

## Non-goals

HEX-CORTEX must not become a trading bot by default.
HEX-CORTEX must not treat execution as its center.
HEX-CORTEX must not be narrowed to software engineering only.
HEX-CORTEX must not assert scientific knowledge or actuator safety without evidence.
HEX-CORTEX must never give a language model direct physical actuator authority.
HEX-CORTEX must not self-modify without tests, lineage, and rollback.
HEX-CORTEX must not grow by adding unverified agents or vague memory.

## Priority order — engineering sequence, not mission limitation

1. Trustworthy cognitive kernel: Brain interchangeability, Router/Cells,
   Workspace/Clock, CanonicalSpine, permissions, independent evidence
2. Cross-domain Knowledge Layer: provenance and retrieval of mathematics,
   physics, molecular science, biology and engineering, with units/invariants
3. Generalizable learning: typed observations, errors, predictions,
   cognitive residuals, skills, anti-forgetting and reversible promotion
4. World models and embodied interfaces: perception, scientific
   simulation and typed state/action contracts for devices/robots/drones
5. First end-to-end validation lane: software repair, where tests give
   objective outcome evidence
6. Additional domain validation lanes: scientific calculations and
   simulator-only robotics; physical execution requires separate safety
7. Research horizon: empirical JEPA/CR-JEPA, science and causal models,
   scientific hypothesis testing, advanced multimodal adaptation

## Architectural laws

### No cognition without lineage

Every important perception, route, decision, action, result, correction, and learning event must have source lineage.

### Memory is not storage

Memory must be selectable, compressed, scoped, visible, and reusable. Raw logs are not intelligence.

### Skills are earned

A skill is not a prompt. A skill candidate must come from accepted learning events, tested workflows, corrections, benchmarks, or external lessons with evidence.

### Execution is optional and gated

Execution is not the identity of HEX-CORTEX. Any destructive or irreversible execution requires a dedicated authorization gate.

### Local-only architecture (decision 2026-10-10)

No HEX-CORTEX server. Hosted reasoning APIs require explicit consent. No local LLM, GPU, or benchmark gate.
