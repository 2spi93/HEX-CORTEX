# HEX-CORTEX V33 — Actual Active Compact World Model on Novel Images

## Why this is the next meaningful experiment

The operator's V32 on Windows:
- **1,994 tests passed**, Ruff clean.
- **108 out of 108** legacy visual transitions are in **one** exact-image
  connected component; 109 distinct image SHA256 values are present.
- One exact image participates across train/validation/test.
- Current 76/16/16 split is NOT image-source-independent.
- The original checkpoint is intact, and its real CPU residual-MLP forward
  already ran on a synthetic zero vector in V31, with input latent 768,
  action 4, hidden 128. Neither test proves visual prediction accuracy.

**KEEP** the existing checkpoint, manifest and all 108 records intact.
Changing split labels after training cannot turn the known test images
into an independent holdout.

## Integrated experiment

\`cortex_novel_visual_pair_v33.py\` and CLI take an **operator-selected**
pair of local, different input/target images AND the actual action
applied between them. They:

1. Check explicit input directory boundaries and sizes, and the V31
   SHA256 chain for the currently active candidate.
2. Hash both selected images and reject any byte-identical image already
   present among **all** 108 training/validation/test images.
3. Verify action dimensionality and **exact action-schema semantics** of
   historical checkpoint; do not compare robotic joint commands against
   a model trained on \`brightness,contrast,translate_x,translate_y\`.
4. Verify DINOv2 frozen encoder descriptor hash is exactly the one
   bound to the checkpoint (\`model_ref\`, \`pooling\`, \`device=cpu\`).
5. **Preflight only:** no encoder, no model, no files written, no network.
6. After independent \`--approve-encode --approve-inference\`, use the
   EXISTING approved frozen DINOv2 encoder with
   \`local_files_only=true\`, actual cached weights and CPU. Load existing
   compact residual MLP \`safetensors\` on CPU in inference mode.
7. Compare the actual predicted next image **embedding** against the
   actual next-image DINOv2 embedding using MSE. Score also the trivial
   identity baseline: "next latent = current latent".
8. Output descriptive scores and hashes only, no image, raw latent or
   full prediction vector; no model promotion, checkpoint modification,
   training, GPU or physical actions.

**Only one pair:** a correctly bounded, previously unseen pair is
a useful *engineering feasibility test*, NOT proof of statistical
generalization, independent provenance, calibrated uncertainty, or
real-world physics. Exact SHA256 novelty cannot rule out near-duplicate
crops, frames of the same scene, leaked source video, or model/pretraining
exposure.

DINOv2 image embeddings are **NOT** interchangeable with V-JEPA 2.1
video embeddings. V33 tests the same original DINOv2 encoder and the
already-trained compact MLP, not a new LeCun/V-JEPA world model.

## Operator data needed

The operator must choose a folder with TWO genuine images not already
used in the legacy \`.hex-cortex/world-model/transitions.jsonl\` data.
They must form an observation→**defined visual transformation**→
target observation pair, with known four-component action values
and original source identity. The four components
\`brightness,contrast,translate_x,translate_y\` describe visual
transformations, not general robotic navigation or force commands.

Do not fabricate a "real" example using the same old reference image
or assume an arbitrary pair of photos has the right action semantics.
For video/robotic source material, a new action-schema model and separately
collected trajectory data will be necessary.

No new images are downloaded or generated by this CLI.

Only after a PASSING novelty preflight, a source check and availability


**Replace all placeholder paths and action values with true inputs.**
\`0.1,0,0,0\` is only an illustration of the shape: it must not be
claimed as the action actually taken. The image root must exist. If you
don't have two genuinely new, action-paired images, do NOT run real
inference; instead collect/source valid input first.

## Future rigorous experiment

- Collect multiple independently sourced, licensed scene/episode groups,
  record per-episode provenance, action timing, camera/sensor metadata
  and use exact same frozen model contract.
- Hold all new scenes apart from ALL prior image sources, not just
  within new train/test partitions. Perform deduplication across full
  source videos, including near-duplicates, with manual verification.
- Compare identity, the original active compact model, and independent
  new candidates by held-out scene: MSE, regressed environments, latency,
  failure cases, uncertainty, and change-point robustness.
- Use V30 grouped latent JSONL when data are properly preprocessed.
- Real V-JEPA video/action backend is a separate branch requiring
  its own weights, data contract and evaluation baseline.
- Never promote or actuate based on a single successful test.
